# Table rotation and why audit tables grow the way they do

*2026-09-25 18:09 UTC*

The `sys_audit` table doesn't grow one row per record update — it grows one row per audited **field** change per update. If a table has 12 audited fields and a single save changes 5 of them, that's 5 rows in `sys_audit` with the same `sys_created_on` timestamp but different `fieldname` values. Bulk imports or data fixes that touch many fields at once are the usual reason `sys_audit` outpaces every other table on an instance within a year.
