# Dictionary overrides on extended tables

*2026-09-26 22:15 UTC*

Dictionary entries don't get copied down when a table extends another — they get looked up by walking the class hierarchy until a match is found. `incident` doesn't have its own `sys_dictionary` row for `short_description` unless someone explicitly created one. That means the first time you "make it mandatory just for Incident," you're actually editing the `task` record, and Problem, Change, and every other child table inherits the change silently.

The failure mode: nobody notices until Problem's create flow starts breaking with a mandatory-field validation nobody added on purpose. Update set shows a `sys_dictionary` change with `name=task`, not `name=incident`, but reviewers usually only skim field labels, not the table column.

The fix is to check whether an override row already exists before editing:

```
var gr = new GlideRecord('sys_dictionary');
gr.addQuery('name', 'incident');
gr.addQuery('element', 'short_description');
gr.query();
if (!gr.next()) {
    gr.initialize();
    gr.name = 'incident';
    gr.element = 'short_description
