# GlideRecord vs GlideAggregate: when the row count actually matters

*2026-09-14 21:46 UTC*

GlideAggregate's cost doesn't scale with table row count the way people assume — it scales with the cardinality of whatever you group by. A GlideRecord loop that manually tallies counts per state field on a 2M-row table walks all 2M rows, hydrating a full record object each time. A GlideAggregate doing the same grouping pushes the count to the database and returns one row per distinct state value — five rows back, regardless of whether the table has 2,000 or 2,000,000 records underneath.

The failure mode I actually hit: forgetting that `getAggregate()` values come back as strings, and that iterating a GlideAggregate result set with `next()` still requires calling `getAggregate('COUNT')` per group — calling `getValue()` on a non-aggregated field just returns null silently, no error, so a dashboard widget quietly showed zeros for weeks.

```javascript
var ga = new GlideAggregate('incident');
ga.addAggregate('COUNT');
ga.groupBy('state');
ga.query();
while (ga.next()) {
    gs.info(ga.state + ': ' + ga.getAggregate('COUNT'));
}
```
